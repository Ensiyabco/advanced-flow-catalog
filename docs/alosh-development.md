# علوش: المرحلة الأولى القابلة للاختبار

افتح `alosh-lab.html` من خادم الموقع المحلي، وأرفق JSON من كتالوجك، ثم اكتب اسم الصنف والمقاس فقط. لا تحتاج التجربة مفتاح API. يعالج المتصفح الملف محليًا دون تخزينه أو رفعه؛ سياسة الصفحة تمنع اتصالات fetch وWebSocket. لا ترفق محادثات أو بيانات شخصية، فهذه واجهة اختبار منتجات فقط.

هذه نواة مطابقة حتمية وليست وكيل محادثة أو نظام RAG كاملًا. لا توجد بعد قناة WhatsApp أو ذاكرة دائمة أو نموذج لغوي أو تنفيذ طلبات. ليست صفحة إدارة، ولا تحتوي بيانات خاصة أو صلاحيات مشرف.

## عقد الأدوات

`Alosh.searchCatalog({query, products, categories})` قراءة فقط. query اسم صنف غير فارغ حتى 200 حرف؛ products مصفوفة، وcategories مصفوفة اختيارية. اسم مطابق بالكامل ومتفرد يعيد `matched`؛ المطابقة الجزئية أو الملتبسة تعيد `clarify`؛ غياب المطابقة يعيد `not_found`؛ المدخلات غير الصالحة تعيد `invalid_input` مع إرشاد التصحيح. النتائج بحد أقصى عشرة أصناف، ولا تشمل التصنيفات الموسومة adminOnly أو التصنيف المحجوز للمشرف. هذه تصفية عرض وليست بديلًا عن صلاحيات مصدر البيانات.

`Alosh.draftProductReply(input)` يستخدم المصدر نفسه ويعيد text وmatches وstatus، مع `mode: suggestion_only` و`requiresReview: true` و`actions: []`. لا توجد أداة إرسال أو تعديل ضمن هذه النواة. واجهات التنفيذ المستقبلية تحتاج بوابة موافقة موثقة في التطبيق والخادم؛ حقل requiresReview وحده ليس آلية صلاحيات.

تُوحّد الأرقام العربية والفارسية وبعض أشكال الحروف العربية. المطابقة بالكلمات الكاملة؛ 2 لا تطابق 20، و25 لا تطابق 20. لا نستنتج المقاسات من اسم قسم. لا يُستخدم stockQty كإثبات توفر لأن تاريخ موثوقيته غير متحقق، ولا تُعرض قيمة سعر غير معتمدة. يبقى orderEnabled=false موقوفًا في صياغة الرد.

## تصميم الذاكرة للمرحلة التالية

لا تحفظ النواة استفسارات أو قواعد حاليًا. عند إضافة ذاكرة دائمة، يتضمن كل سجل: rule_id وscope (business/personal) ونص القاعدة وsource وcreated_at وapproved_by وapproved_at وvalid_from وvalid_until وsupersedes وrevoked_at. اعتماد القاعدة يأتي من قناة علي الموثوقة، لا من نص العميل أو ملف الكتالوج. يجب اختبار الفصل بين النطاقات، والإلغاء والتصحيح وانتهاء الصلاحية قبل الاستخدام. لا تحفظ حالة المخزون أو السعر كحقيقة دائمة، ولا تعيد ذكر بيانات من ذاكرة شخصية في رد تجاري. لا تستخدم المثال التعليمي memory_store.py في الإنتاج.

## التحقق

شغّل `node --test tests/*.test.cjs`. اختبارات الاسترجاع مستقلة عن صياغة الرد: حالات عربية واسم ناقص ومقاس غير موجود وأصناف موقوفة وتصنيفات مشرف ومدخل يحاول تغيير التعليمات. التقييم الحالي على عينات مصطنعة صغيرة؛ نجاحها لا يثبت جودة الاسترجاع على جميع المنتجات أو فهم رسائل العملاء. قبل ربط نموذج لغوي أو كتالوج حي، أضف مجموعة استفسارات عربية منقحة ومعتمدة، وقِس Recall@10 وإخفاقات المقاسات والتوفر بصورة منفصلة.

اختبارات السلة تولد 1000 عينة لكل صفحة ببذرة ثابتة وتثبت حفظ مجموع كل وحدة، واستقلال الحبة والكرتون، وعدم تغيير المصدر، وثبات التطبيع، وتختبر حد دقة الأعداد صراحة. لا تحتاج مكتبات إضافية. GitHub Actions يشغل الاختبارات تلقائيًا عند فتح طلب دمج أو تحديث main.
